# 仿真协议与协议级测试矩阵（M3-4）

> 范围：主进程（`esp32-ide`）与仿真子进程（`esp32-sim`）之间的 **JSON Lines 线协议**，
> 以及围绕它组织的协议级测试矩阵。硬件行为（真实 QEMU DLL）在 C 层覆盖。

## 一、线协议

每行一个 JSON，走子进程 stdin/stdout：

```text
主进程 → 子进程：  {"id":<n>,"cmd":"<命令>", ...}
子进程 → 主进程：  {"reply":<n>,"ok":true,"data":...}          # 命令响应
                   {"event":"<事件名>","payload":...}          # 异步事件
                   {"log":"..."}                               # 日志
```

命令：`stop` / `pause` / `resume` / `pin_write{pin,value}` / `uart_send{uart,data}` /
`pins` / `status` / `uart_poll` / `set_apin{chn,value}`。

事件：`gpio-update{pin,gpio,value,dir}` / `uart-data{flushed,data}` / `sim-status` /
`sim-error{message}`。实现见 `src-tauri/src/sim/protocol.rs` 与 `sim_worker.rs`。

启动成功判据（`worker_host::health_pass`，纯函数）：引脚活动累计 ≥4 次、首次活动距今
≥3 秒、且最近 2 秒内仍有活动；或 UART ≥1500 字节。避免把"ROM 阶段抖几下后卡死"误判为成功。

## 二、测试矩阵

| 层 | 目标 | 是否需 QEMU DLL | CI | 用例文件 |
| --- | --- | --- | --- | --- |
| A | 线协议 + 宿主状态机（用 `fm-fake-worker` 替身走真实进程链路） | 否 | ✅ | `tests/worker_protocol.rs`、`sim/protocol.rs` |
| B | 引脚状态表行为（默认态/输出/输入驱动/复位/越界） | 否 | ✅ | `tests/pins_matrix.rs` |
| C | 真实 QEMU 行为（固件冒烟/UART/多引脚并发/串口批处理） | 是 | ❌（`#[ignore]`） | `tests/behavior_matrix.rs` 等 |
| D | 前端网表快照（标准教学电路 golden snapshot） | 否 | ✅ | `src/circuit/__tests__/snapshot.test.ts` |

### A 层：线协议与宿主（CI 可跑，约 16 项 + protocol 单测 6 项）

| 编号 | 用例 | 验证点 |
| --- | --- | --- |
| H01 | 健康启动 | 状态 Running、只拉起 1 个子进程、gpio-update ≥4 条、有"仿真已启动"日志 |
| H02 | 健康判据·持续活动 | 活动≥4/跨度≥3s/最近活跃 → 通过；UART≥1500 兜底通过 |
| H03 | 健康判据·ROM 卡死 | 活动不足/跨度不足/最近活动过期/UART 差 1 字节 → 全部判失败 |
| H04 | 自动重试 | 第一次被拉起即死 → 自动换新进程 → Running；日志含"正在重试"；marker 计数 2 |
| H05 | 重试耗尽 | 两次都死 → 返回"均未成功"、状态 Stopped |
| H06 | 致命错误 | sim-error 事件 → start 返回错误、不重试 |
| H07 | 命令往返 | pins / pin_write / uart_send / set_apin / pause / resume 全部 OK，数据正确 |
| H08 | 停止 | stop 后子进程回收、状态 Stopped |
| H09 | 无响应超时 | 子进程不应答 → write_pin 超时报错；stop 能强杀不卡死 |
| P01–P06 | protocol.rs 单测 | 命令帧构造、响应/事件帧解析、日志、畸形行、序列化还原 |

### B 层：引脚状态表（CI 可跑，6 项）

| 编号 | 用例 | 验证点 |
| --- | --- | --- |
| P01 | 默认态 | 全输入全低；pin24=GPIO2、pin25=GPIO0；无外部驱动 |
| P02 | 输出回调 | 记录电平与方向；无变化不触发事件（去抖） |
| P03 | 外部输入驱动 | set_input 记录电平并入 forced_inputs；MCU 接管后停止重推 |
| P04 | 方向回调 | 方向翻转 |
| P05 | 复位清空 | 电平/方向/外部驱动全部清空 |
| P06 | 引脚边界 | 越界读写不 panic、返回 None |

### C 层：真实 QEMU 行为（本机 `--include-ignored`，1 项组合用例）

| 编号 | 用例 | 验证点 |

## 三、怎么跑

```powershell
# CI 同款（A/B/D 层，不需要 DLL）
npm run test:rust

# 本地全量（含 C 层，需要 lib/qemu 与固件）
npm run test:rust:local

# 只看某一层
cargo test --manifest-path src-tauri/Cargo.toml --test worker_protocol
cargo test --manifest-path src-tauri/Cargo.toml --test pins_matrix
cargo test --manifest-path src-tauri/Cargo.toml --test behavior_matrix -- --include-ignored --nocapture
```

## 四、假 worker（`src/bin/fake_worker.rs`）

协议替身，不加载 DLL。用环境变量编排行为（见文件头注释）：`FAKE_EVENTS` 事件脚本、
`FAKE_EVENT_GAP_MS` 间隔、`FAKE_MARKER_FILE` 启动计数、`FAKE_SIM_ERROR` 致命错误、
`FAKE_EXIT_AFTER_MS`/`FAKE_DIE_AT_SPAWN` 死亡时机、`FAKE_IGNORE_CMDS` 无响应。
宿主通过既有环境变量 `ESP32_IDE_SIM_WORKER` 指定它。
