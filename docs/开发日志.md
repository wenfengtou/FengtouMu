  表现为点击"运行"闪退 0xC0000005）。

## 2026-09-11 · 子进程架构改造 + UI 自动化

- **架构改造：仿真移入独立子进程**
  - 新增二进制 `esp32-sim`（`src/bin/sim_worker.rs`）：独占加载 QEMU DLL，通过
    stdin/stdout 的 JSON Lines 协议与主进程通信；
  - 主进程改为"宿主"（`src/sim/worker_host.rs`）：spawn 子进程、转发事件、健康检测、
    卡死自动重试、命令代理。主进程**不再加载 DLL**。
  - 收益：可无限次重复运行；冷启动卡死时杀掉子进程换新进程重试；子进程异常不影响界面，**不再闪退**。
- **健康判据迭代**（避免把 ROM 卡死误判为"启动成功"）：
  - 初版"任意引脚变化"过于宽松（卡死前也可能有一两次抖动）；
  - 二版改为"引脚活动持续：累计 ≥2 次且最近 2 秒内仍有活动，或 UART 输出 ≥1500 字节"；
  - 三版（M2 期间收紧，见下）要求"累计 ≥4 次、首次活动距今 ≥3 秒、最近 2 秒内仍有活动，或 UART ≥1500 字节"——QEMU 在 ROM 阶段抖几下后卡死的情形不再被误判为成功。
- **UI 自动化**：新增 `scripts/ui_drive.mjs`，通过 WebView2 远程调试（CDP）驱动**真实界面**：
  自动加载 DLL → 点击"运行"（内部自动重试）→ 采样板卡 LED 翻转 → 点击"停止" → 校验子进程退出。
- **构建脚本**：新增 `scripts/build_release.ps1`（一键：编译主程序 + 仿真子进程 → 同步打包资源 →
  `tauri build` 产出 exe / MSI / NSIS）。
- **验证**：同一应用会话内连续两次 `运行 → LED 闪烁（15 秒 19/18 次）→ 停止` 全部通过，全程无闪退。

- 验证结果（`npm run build:release` + 26 项单元测试 + 4 条 UI 自动化链路全部通过）：
  - 前端单元测试 26 项通过（`npm run test:unit`）：网表 4、行为 9、图纸 9、目录 4。
  - UI 自动化（真实鼠标事件，`npm run test:ui`，共 4 条链路）：A 板卡视图 LED 翻转 49 次；B 电路图放置 LED → 连线 GPIO2/GND → 运行 → 画布 LED 翻转 32 次；C 放置按键 → 连线 GPIO0/GND → 运行 → 按住时 `data-pressed=1`；D 放置电位器 → SIG 接 GPIO34 → 运行 → 拖动旋钮 → 读数 0.5 → 1.0 且注入无报错。
  - Rust 侧新增 `tests/button_injection.rs`，验证注入 API 与 QEMU 同步回调链路。
  - 发布产物：`src-tauri/target/release/esp32-ide.exe` 与 MSI/NSIS 安装包。
- 验证期间发现并修复的问题：
  - **启动健康判据过松**：QEMU 在 ROM 阶段抖出两次引脚事件后卡死，判据即判定"启动成功"，表现为界面显示运行中但 LED 一次都不翻转。现改为"累计 ≥4 次、首次活动距今 ≥3 秒且最近 2 秒内仍有活动，或 UART ≥1500 字节"，实测启动耗时 6.7–10.6 秒（真实启动），ROM 卡死会被识别并自动换进程重试。
  - **按键可点击区域过小**：此前只有按键外壳 `<rect>` 响应按下，点中"按键"标签（元件中心）不会触发。现整块元件任意位置都可按下（引脚自身的 `mousedown` 会 `stopPropagation`，因此接线不会误触发）。
  - **UI 自动化落点探测**：画布上元件会互相压盖（新增元件按 `y = 80 + (n-1) × 50` 叠加）、导线也可能横穿元件。脚本改用 `document.elementFromPoint` 逐候选点探测真正命中目标元件的落点；同时每条链路开始前先确保仿真已停止，避免上一条链路失败残留运行态干扰后续断言。
- 引擎侧的两个发现：
  - QEMU 每次读取 GPIO 输入寄存器都会通过 `picsimlab_dir_pin(-1, ...)` 请求同步，此前我们忽略了该请求。现已按 PICSimLab 的做法，把外部驱动的电平重新推回模型（`SET_PIN_FN` + `PinTable::forced_inputs`）。
  - 已知限制：固件以 `INPUT_PULLUP` 读取引脚时，注入的低电平无法稳定保持——实测注入后 LED 继续闪烁、串口未出现 "BOOT pressed"；若以 50ms 频率反复注入，串口会零星出现该输出，说明电平能到达固件但不能保持。因此画布按键目前保证界面与注入链路正确，运行期"按键改变固件行为"仍需从 QEMU 模型侧继续定位。

## 2026-09-12 · 修复：一键编译「exit 0 却报编译失败」

- 现象：点「编译」后提示 `编译失败: 编译失败（arduino-cli exit Some(0)）: Sketch uses 285316 bytes (21%) …`，而 arduino-cli 的退出码是 0、输出也是成功的体积统计。
- 根因：`buildchain.rs` 用 `sketch_dir.file_stem()` 拼产物名 —— 目录 `picsimlab_gpio_demo` 的 `file_stem()` 是 `picsimlab_gpio_demo`，于是去找 `picsimlab_gpio_demo.merged.bin`，而 arduino-cli 实际产出的是 `picsimlab_gpio_demo.ino.merged.bin`；找不到就落进"失败"分支，还把成功的 stdout 当错误信息一起打了出来。这条路径此前没被真正验证过（M1 的固件是手工编译+合并准备好的）。
- 修复：
  - 新增 `sketch_name()`：优先取与目录同名的 `.ino`，否则取目录内任意 `.ino`（并据此给出"目录名与 .ino 需同名"的直白提示）。
  - 新增 `find_merged_bin()`：按 `<sketch>.ino.merged.bin` → `<目录名>.merged.bin` → 输出目录里最新的 `*.merged.bin` 依次定位，不再依赖单一命名。
  - 退出码非 0 才叫失败；退出码为 0 但找不到合并镜像时，错误信息里列出输出目录与已有产物，并提示保留 `FlashMode=dio,FlashFreq=40,FlashSize=4M`。
  - 前置校验移到「调用 arduino-cli」之前：目录不存在 / 没有 `.ino` / 目录名与 `.ino` 不同名都能立刻给出可读原因。
- 验证：
  - 新增 `src-tauri/tests/buildchain.rs`：4 项不需要 arduino-cli 的用例（命名优先级、`<sketch>.ino.merged.bin` 命中、兜底命名与空目录、前置校验提示）；另 1 项 `#[ignore]` 用例真实调用 arduino-cli 编译 demo 草图，实测产出 `picsimlab_gpio_demo.ino.merged.bin`（4194304 字节）。
  - UI 自动化新增「H 一键编译」链路：真实点击「编译」→ 断言出现"正在编译"→"编译成功"，且固件路径切到 `*.ino.merged.bin`。

## 2026-09-12 · 修复：编译编的不是编辑器里的代码（改了代码"没生效"）

- 现象：用户打开工程 `lwf.fmp`，把代码改成 5 秒闪烁并加串口打印，点「编译 → 运行」后闪烁周期不变、串口也没有预期的打印。
- 根因：编辑器里的代码只存在内存 / 工程文件里，而 arduino-cli 编译的是**磁盘上的草图目录** —— 两者不同步时，编出来的还是旧固件。`lwf.fmp` 的 `sketchDir` 指向演示目录，磁盘上的 `.ino` 仍是 500ms 演示版，所以"改 5s 没生效"；串口其实有输出，只是那是旧固件的打印，且 QEMU 的 UART 按波特率模拟、输出明显滞后（见下方已知限制），很容易被误认为"没有日志"。
- 修复：
  - `compile()` 新增 `code` 参数：编译前经 `sync_sketch_source()` 把编辑器内容写入 `<sketchDir>/<sketch>.ino`。内容一致时不写盘；首次覆盖时把原文件备份为 `<sketch>.ino.bak`（只备份一次，不覆盖已有备份）。
  - 成功提示注明「已把编辑器内容写入 …（原文件已备份为 …）」；前端 `compileCurrent()` 把当前编辑器内容与工程 fqbn 一起传给编译链。
- 验证：
  - 新增 `src-tauri/tests/user_sketch_blink.rs`（`#[ignore]`，本地跑）：临时草图先放 500ms 旧固件，用 5 秒新代码编译 → 断言磁盘 `.ino` 已被更新、存在备份、合并镜像为 4MB → 起仿真实测 **LED 相邻翻转间隔 ≈ 4.99–5.00 秒**（多次运行均如此），证明编出来的确实是编辑器里的代码。
  - `buildchain` 新增 `sync_sketch_source` 单元用例（内容一致不写盘、覆盖时备份一次、不重复备份）。
  - UI 自动化「H 一键编译」增加断言：编译成功提示里必须出现「编辑器内容已同步到草图目录」。
- 已知限制（与"看不到串口日志"直接相关）：
  - QEMU 的 UART 按波特率模拟，输出明显滞后于 CPU 时间：固件 setup 里的 `Serial.println` 可能要等 20–40 秒才在终端出现，ROM 启动日志也是逐段冒出来的。
  - 仿真运行约 20 秒后，本固件会偶发崩溃（Guru Meditation）进入重启循环，极端情况下 QEMU 进程会直接中止 —— 与早期 demo 固件的崩溃行为一致，属模型侧问题，待后续定位（M2 遗留的按键保持问题同源）。

## 关键决策一览

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 仿真引擎复用方式 | 复用 PICSimLab 的 `libqemu-xtensa.dll`，Rust 侧 FFI 封装 | 已有可用构建，无需重造仿真轮子 |
| 固件编译参数 | 固定 `dio / 40MHz / 4MB` | 80MHz/QIO 固件在 QEMU 下 flash 初始化失败 |
| 仿真运行位置 | **独立子进程** `esp32-sim` | QEMU DLL 不支持同进程二次初始化、不可安全卸载 |
| 启动成功判据 | 引脚活动持续（≥4 次、跨度 ≥3 秒、最近 2 秒内仍活动）或 UART ≥1500B | 排除 ROM 冷启动卡死的误判 |
| 桌面技术栈 | Tauri 2（Rust 后端 + Web 前端） | 体积小、Rust 可直接 FFI 调 DLL |
| 电路图编辑器 | 自研 SVG 画布 + 复用 wokwi-elements，格式对齐 `diagram.json` | 官方仅开源组件，编辑器需自研（见设计方案 7.3） |
| 工程文件格式 | 单个 `.fmp`（JSON，内含 `diagram.json` 文本） | 电路语义留在前端，Rust 侧只负责存取 |
| 自动保存位置 | 应用数据目录 `autosave.fmp`，每 30 秒一次 | 不污染用户工程目录，异常退出后可恢复 |
| CI 运行范围 | 只跑不需要 QEMU 的用例，DLL 用例 `#[ignore]` | 仓库不含大体积二进制，CI 无法提供 DLL |
