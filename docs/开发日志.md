## 2026-09-05 · QEMU 动态库打通

- 从 `lcgamboa/qemu` 的 `picsimlab-esp32` 分支（QEMU 9.2.2 基线）编译出 **`libqemu-xtensa.dll`**，
  取代此前的 exe 形态，供 PICSimLab / 自研 IDE 以 `LoadLibrary` 方式调用。
- 关键工作：在 `system/cpus.c` 增加 iothread 锁兼容别名
  （`qemu_mutex_lock_iothread_impl` / `qemu_mutex_unlock_iothread`），
  以适配预编译版 PICSimLab 0.9.2 按旧符号名解析的行为。
- 验证：PICSimLab 加载成功；GPIO 演示固件 LED 闪烁、BOOT 按键控制均正常（回调链路完整）。

## 2026-09-06 · 项目立项，M1 MVP 完成

- 搭建 `esp32-ide` 工程骨架：**Tauri 2 + React + TypeScript + Monaco Editor**。
- 完成 M1 范围：
  - Rust 侧 DLL 封装（`libloading` + `#[repr(C)]` 回调结构体，21 个符号核验）；
  - 固定板卡视图（ESP32 DevKitC，板载 LED = GPIO2 / BOOT 按键 = GPIO0，38 引脚状态可视化）；
  - 串口终端（UART0 收发）；
  - 编译链封装（调用 arduino-cli，产出 4MB 合并镜像 + efuse 文件）。
- **踩坑 1：固件编译参数**
  用 Arduino 默认 fqbn（80MHz/QIO）编译的固件在 QEMU 下 flash 初始化必失败
  （日志 `qio_mode: Failed to set QIE bit` → `assert failed: init_flash`）。
  改为 **`FlashMode=dio,FlashFreq=40,FlashSize=4M,PartitionScheme=default,PSRAM=disabled`**
  后立即通过。该参数已固化为编译链默认值。
- **验证**：新增无 GUI 集成测试 `src-tauri/tests/sim_integration.rs`，
  覆盖 `DLL 加载 → 仿真启动 → GPIO 回调 → LED 闪烁` 全链路，实测 LED 翻转正常。
- **踩坑 2（引出架构改造）**：PICSimLab 的 QEMU 构建**不支持同进程二次 `qemu_init`**
  （第二次会耗尽静态区直接退出进程），且**不能安全卸载**（`FreeLibrary` 后残留线程访问已释放代码，
  表现为点击"运行"闪退 0xC0000005）。

## 2026-09-11 · 子进程架构改造 + UI 自动化

- **架构改造：仿真移入独立子进程**
  - 新增二进制 `esp32-sim`（`src/bin/sim_worker.rs`）：独占加载 QEMU DLL，通过
    stdin/stdout 的 JSON Lines 协议与主进程通信；
  - 主进程改为"宿主"（`src/sim/worker_host.rs`）：spawn 子进程、转发事件、健康检测、
    卡死自动重试、命令代理。主进程**不再加载 DLL**。
  - 收益：可无限次重复运行；冷启动卡死时杀掉子进程换新进程重试；子进程异常不影响界面，**不再闪退**。
- **健康判据迭代**（避免把 ROM 卡死误判为"启动成功"）：
  - 初版"任意引脚变化"过于宽松（卡死前也可能有一两次抖动）；
  - 改为 **引脚活动持续：累计 ≥2 次且最近 2 秒内仍有活动，或 UART 输出 ≥1500 字节**。
- **UI 自动化**：新增 `scripts/ui_drive.mjs`，通过 WebView2 远程调试（CDP）驱动**真实界面**：
  自动加载 DLL → 点击"运行"（内部自动重试）→ 采样板卡 LED 翻转 → 点击"停止" → 校验子进程退出。
- **构建脚本**：新增 `scripts/build_release.ps1`（一键：编译主程序 + 仿真子进程 → 同步打包资源 →
  `tauri build` 产出 exe / MSI / NSIS）。
- **验证**：同一应用会话内连续两次 `运行 → LED 闪烁（15 秒 19/18 次）→ 停止` 全部通过，全程无闪退。

- **从 fork 重新编译 DLL**（`docs/build-qemu-dll-windows.md` 记录了完整步骤）：
  - **踩坑 3**：`--enable-debug` 会产出 `-O0 + debug_tcg` 的调试版 QEMU，
    实测固件启动后崩溃（EXCCAUSE）、且大量冷启动卡死。正确配置为
    `--target-list=xtensa-softmmu --enable-slirp --enable-gcrypt --disable-werror --disable-pie --disable-docs --disable-plugins`（即 `-O2`、关闭 debug_tcg/plugins）。

    否则 MinGW 不会把全局符号写入 PE 导出表，表现为"DLL 能加载但 `qemu_init` 找不到"。
  - 产物：`libqemu-xtensa.dll`（68.5 MB），17 个关键符号导出齐全。
- **验证与部署**：集成测试 + UI 自动化双通过；新 DLL 已部署到
  `FengtouMu/lib/qemu/`（IDE 使用）与 `PICSimLab/picsimlab_win64/lib/qemu/`。
- **收敛**：删除 `myself`（2.1 GB）——其改动已全部迁入 fork，DLL 亦不再依赖该目录。

## 关键决策一览

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 仿真引擎复用方式 | 复用 PICSimLab 的 `libqemu-xtensa.dll`，Rust 侧 FFI 封装 | 已有可用构建，无需重造仿真轮子 |
| 固件编译参数 | 固定 `dio / 40MHz / 4MB` | 80MHz/QIO 固件在 QEMU 下 flash 初始化失败 |
| 仿真运行位置 | **独立子进程** `esp32-sim` | QEMU DLL 不支持同进程二次初始化、不可安全卸载 |
| 启动成功判据 | 引脚活动持续（≥2 次且最近 2 秒内）或 UART ≥1500B | 排除 ROM 冷启动卡死的误判 |
| 桌面技术栈 | Tauri 2（Rust 后端 + Web 前端） | 体积小、Rust 可直接 FFI 调 DLL |
| 电路图编辑器 | 自研 SVG 画布 + 复用 wokwi-elements，格式对齐 `diagram.json` | 官方仅开源组件，编辑器需自研（见设计方案 7.3） |

## 当前状态

- **已完成（M1 MVP）**：代码编辑 → 一键编译 → 本地仿真 → 板卡/串口可视化，全链路可用并已自动化验证。
- **可用命令**：
  - `npm run build:release` — 一键构建（exe + 安装包）
  - `npm run test:ui` — UI 自动化验证（连续两次运行/停止）
  - `cargo test --test sim_integration -- --nocapture` — 无 GUI 集成测试
- **已知限制**：
  - 宿主负载高（如远程桌面/录屏占用 CPU）时，QEMU 冷启动偶发卡死；应用会自动重试，仍失败则提示重新运行。
  - 产品名/进程名仍为 `esp32-ide`（文件夹与仓库已改为 FengtouMu）。
  - `lib/qemu` 等大体积二进制不入库，首次构建需按 `docs/build-qemu-dll-windows.md` 自行编译或从本地拷贝。
