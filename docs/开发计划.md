# 开发计划

> 项目：FengtouMu（ESP32 离线仿真 IDE）
> 起点：M1 已完成并通过自动化验证（详见 `docs/开发日志.md`）
> 日期：2026-09-12

## 一、基线

已有能力：

- 代码编辑（Monaco）、一键编译（arduino-cli，固定 `dio/40MHz/4MB`）、串口终端（UART0）
- 板卡视图（ESP32 DevKitC，38 引脚状态、板载 LED=GPIO2、BOOT 按键=GPIO0）
- 仿真进程模型：QEMU 动态库运行于独立子进程 `esp32-sim`，支持冷启动卡死自动重试，仿真异常不影响界面
- 验证手段：无 GUI 集成测试（`src-tauri/tests/sim_integration.rs`）、UI 自动化（`scripts/ui_drive.mjs`）、一键构建（`scripts/build_release.ps1`）

已知约束：

- 宿主负载高时 QEMU 冷启动偶发卡死，已用重试缓解，仍可能失败一次
- `lib/qemu` 等大体积二进制不入库，新环境需要先按 `docs/build-qemu-dll-windows.md` 准备
- 前端状态集中在 `App.tsx`，尚无工程文件与数据模型
- 仅支持 ESP32 与 DevKitC

## 二、目标与范围

M2 的目标是把"只有板卡"变成"可以搭电路"：元件能拖到画布上、用导线连到引脚，运行时随固件变化。

M3 的目标是把它变成能长期使用的工具：工程能存能带、环境问题能自查、回归有测试与流水线兜底。

M4 面向课堂与进阶能力：示例与引导、可分享的成果、AI 辅助、模拟电路求解。

明确不在 M2 与 M3 范围内：多板卡支持、真实 SPICE 求解、在线下载依赖、AI 助手。这四项都依赖更靠前的地基，留到 M4。

## 七、关键决策

电路模型放前端。引脚、网表、元件行为都在 TypeScript 侧，Rust 保持"只做 I/O 与进程管理"的边界，避免每次加元件都要改后端。

工程格式对齐 Wokwi。沿用 `diagram.json` 的 `parts`/`connections` 结构，学生作品可以在 Wokwi 在线版与本地之间往返。

元件外观复用 `wokwi-elements`，行为自研。上游只提供外观不提供仿真，因此元件的电气行为必须自己实现；M2 只做四个元件，控制范围。

保持离线与进程模型。不引入 Python 运行时，不改为在线下载依赖；仿真继续运行于独立子进程，保留卡死重试。

## 八、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 元件行为模型工作量被低估 | M2 与 M3 拖期 | M2 只做 LED、按键、电阻、电位器四个；其余按教学优先级排队 |
| 前端状态重构引入回归 | 现有可用功能被破坏 | 分两步迁移，先搬仿真状态再搬编辑器状态；每步用现有 UI 自动化脚本回归 |
| SVG 画布交互细节多 | 拖拽与连线体验反复 | 先做最小交互集（放置、拖拽、选中、删除、连线），缩放与对齐后置 |
| 模拟电路求解复杂度高 | M4 不可控 | 先数字化近似，真 SPICE 作为独立探索项，允许延后或裁剪 |
| QEMU 冷启动偶发卡死 | 用户体验受损 | 保留自动重试与明确提示；继续观察是否与宿主负载强相关，必要时给出负载建议 |
| 大体积二进制不入库 | 新环境搭建门槛高 | M3-2 环境自检 + 现有 DLL 编译文档；必要时在仓库提供校验脚本 |
| 单板卡限制 | 教学场景受限 | M4-5 做引擎抽象；短期不承诺多板卡 |

## 九、起步顺序

第一批工作按以下顺序推进，先打通一条最窄的端到端路径：

1. 前端状态分层（M2-2），把仿真相关状态从 `App.tsx` 挪出，为电路数据模型腾位置
2. 引脚与网表抽象（M2-1），配套单元测试
3. 画布骨架（M2-3 的最小集：放置、拖拽、选中、删除、连线）
4. diagram.json 读写（M2-4）
5. LED 与按键两个元件打通端到端（M2-5 的前半），用现有 GPIO demo 固件实测
6. 补齐电阻与电位器，补测试与文档（M2-5 后半、M2-6）

这条路径在第 5 步即可得到可演示的结果：画布上的 LED 跟着固件闪烁，按下画布上的按键能改变固件行为。

## 十、验收机制

单元与集成测试。前端用 Vitest 覆盖网表、引脚路由、元件行为；Rust 侧沿用 `cargo test`。

协议级用例。按交互协议组织，覆盖 GPIO、UART、多引脚并发与示例固件冒烟，作为 M2 与 M3 的回归基线。

UI 自动化。现有 `scripts/ui_drive.mjs` 扩展为"打开工程 → 放置元件 → 连线 → 运行 → 断言元件状态"，作为发布前的最后一道检查。

CI 门禁。M3-3 之后，push 与 PR 必须通过前端构建、前端测试与 Rust 测试。
